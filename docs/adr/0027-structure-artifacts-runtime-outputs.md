# ADR-0027: Structure artifacts are runtime outputs

| Field | Value |
|---|---|
| Status | Accepted — Design B |
| Date | 2026-07-13 |
| Deciders | skipp-dev |
| Related | ADR-0001; `docs/structure_contract_architecture.md` |

## Context

The repository historically committed `reports/smc_structure_artifact.json`, a legacy 1D
fallback. Its generation timestamp predated its data by roughly two years. Because primary
per-timeframe artifacts are generated by production and measurement workflows and ignored by
Git, that stale fallback also made a clean checkout appear to provide current structure.

## Decision

Adopt Design B:

1. Structure artifacts are materialized pipeline outputs, not repository fixtures.
2. A clean checkout honestly reports no structure provider and fails closed for structure input.
3. Per-timeframe manifests and referenced artifacts are the primary production contract.
4. The legacy single-file format remains supported only as an explicit compatibility fallback.
5. Production and release workflows prove primary artifact availability before consumption.

## Consequences

- Repository-state audits no longer confuse frozen market data with a live provider.
- Consumers must tolerate an unavailable provider and may not infer neutral structure evidence.
- Workflows that consume structure fail before scoring or release when materialization is absent.
- Legacy deployments remain readable, but the fallback does not satisfy the primary workflow gate.

## Enforcement

- `tests/test_smc_integration_structure_artifact_provider.py` pins absent, per-TF, and legacy modes.
- `tests/test_smc_integration_structure_category_coverage.py` pins honest clean-checkout coverage.
- Production/benchmark and release workflows invoke the structure-artifact availability check.
